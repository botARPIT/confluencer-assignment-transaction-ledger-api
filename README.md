# Confluencer Transaction Ledger

A small transaction ledger API for the Full Stack Developer Assessment. It creates accounts with a system-generated ID, zero opening balance, and creation timestamp; supports credit and debit transactions; and provides balances, transaction history, and atomic account-to-account transfers.

## Stack

- FastAPI with generated OpenAPI documentation
- Pydantic v2 validation and strict request models
- SQLAlchemy 2 and Alembic migrations
- SQLite for local development; PostgreSQL in Docker Compose
- Browser UI, Postman collection, five unit tests, and one integration test

## Run with Docker

```bash
docker compose up --build
```

Open [http://localhost:8000/](http://localhost:8000/) for the UI, [http://localhost:8000/docs](http://localhost:8000/docs) for Swagger UI, or [http://localhost:8000/redoc](http://localhost:8000/redoc) for ReDoc. Stop with `Ctrl+C`; use `docker compose down -v` to also remove the database volume.

## Run locally with SQLite

Requires Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
```

The SQLite database is created at `./ledger.db`. Visit `http://localhost:8000/` and `http://localhost:8000/docs`. Run tests in the activated environment with `python -m pytest`.

The UI uses the current origin when served by FastAPI. If you open `static/index.html` directly as a file, it targets `http://localhost:8000`; a different API host can be supplied with the `api` query parameter.

## PostgreSQL outside Docker

Set `DATABASE_URL` before running Alembic or the API:

```bash
export DATABASE_URL='postgresql+psycopg://ledger:ledger@localhost:5432/ledger'
alembic upgrade head
uvicorn app.main:app --reload
```

## API

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Health check |
| `POST` | `/accounts` | Create an account with zero balance |
| `GET` | `/accounts/{account_id}` | Read `account_id` and current balance |
| `POST` | `/accounts/{account_id}/transactions` | Apply a credit or debit |
| `GET` | `/accounts/{account_id}/transactions` | Filter and paginate history (`type`, `page`, `limit`) |
| `POST` | `/transfers` | Atomically transfer funds between accounts |

Example transaction body (use a string for the decimal amount):

```json
{
  "type": "credit",
  "amount": "50.00",
  "description": "Payment received",
  "reference_id": "payment-001"
}
```

The account ID and creation timestamp are generated by the server. The client cannot set an opening balance. Transaction amounts must be positive and have at most two decimal places. Each reference ID must be unique within its account. Insufficient funds and duplicate references return `409 Conflict`. Unknown accounts return `404`; malformed or extra request fields return `422`.

History accepts an optional `type=credit|debit`, `page` (default `1`), and `limit` (default `100`, maximum `500`). It returns `transactions`, `page`, `limit`, `total_records`, and `total_pages`, ordered newest first.

A transfer records a debit on the source account and a credit on the destination account in one database transaction. Both accounts must exist, the source must have sufficient balance, and the reference ID must be unused on both accounts. A failed transfer leaves both balances and histories unchanged.

## Postman

Import `postman/Confluencer-Ledger.postman_collection.json`. Create both accounts first; the collection saves their IDs. The remaining requests demonstrate balance lookup, credit, debit, filtered history, and transfer.

## Tests

`tests/test_ledger.py` contains five unit tests for balance rules. `tests/test_api_integration.py` checks account creation, credit/debit posting, duplicate and insufficient-funds rejection, balance retrieval, filtering, pagination, and atomic transfers against an isolated in-memory SQLite database.

## Assumptions

- Accounts use one currency; currency conversion is outside scope.
- Account creation starts at zero, and clients cannot set an opening balance.
- A reference ID is unique per account. A transfer uses the same reference ID for its source debit and destination credit.
- Transfers to the same account are rejected.
- Authentication and authorization are outside this assessment-sized implementation.
